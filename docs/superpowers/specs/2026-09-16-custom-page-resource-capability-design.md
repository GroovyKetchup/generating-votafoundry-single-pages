# 自定义页面业务资源能力探测与旧版降级设计

## 背景

新版本 CDP 宿主识别页面中的 `data-cdp-internal-resources` 清单，并把页面相对资源解析到当前业务域的 `cdn_cdp/{businessDomain}/`。webPage 服务通过 `/wp-cdn/api` 提供资源列举、上传、导出和导入能力。

CDP 前端与 webPage 后端独立部署。单页生成 Agent 能访问 webPage 服务，但不能假定 CDP 部署根，也没有可靠途径读取目标环境实际部署的 CDP 版本。因此，生成阶段无法自动验证完整的业务资源管理能力。

## 目标

- 页面需要业务资源时，在生成阶段探测 webPage 资源接口。
- 接口可用时不中断 vibe coding，直接完成统一资源纳管。
- 接口不存在时，让用户在升级平台和旧版非托管生成之间明确选择。
- 不把兼容策略转嫁给页面运行时或实际应用用户。

## 最低版本

- CDP：`1.20.0`
- webPage：`1.4.2`

版本号只用于交付提醒和升级指导；生成分支不通过版本字符串判断。

## 能力探测

仅当待生成页面确实需要业务资源时，Agent 才调用一次 `GET /wp-cdn/api/listFiles`。不需要业务资源的页面不为能力探测产生额外请求或用户交互。

探测成功必须同时满足：

1. HTTP 响应为成功状态；
2. 响应符合接口既定信封协议；
3. `state` 为数字或字符串 `200`，且 `data` 为资源数组。

该探测只证明 webPage 资源接口可用，不证明 CDP 前端版本满足要求。

## 决策矩阵

| 探测结果 | Agent 行为 |
|---|---|
| 接口可用且协议正确 | 不询问用户，直接执行列举、复用、上传、写入 manifest 和机械校验 |
| 明确不存在或路由不支持 | 暂停资源流程，让用户选择升级后继续或使用旧版非托管模式 |
| `401` / `403` | 按登录或权限问题处理，不判定为旧版本，不提供降级分支 |
| 网络错误、超时、`5xx` | 按服务异常处理，不判定为旧版本，不提供降级分支 |
| 成功 HTTP 状态但响应协议不匹配 | 判定目标资源接口不可用，进入升级或旧版非托管选择 |
| 其他 HTTP `4xx`，或合法信封中 `state` 不为 `200` | 按接口返回的具体错误处理，不推断版本，不提供降级分支 |

“接口明确不存在或路由不支持”包括 `404`、`405`。响应协议不匹配覆盖网关将未知路径回退为 HTML 等情况。

## 接口不可用时的用户选择

Agent 只提供以下两个选择：

1. 升级 CDP 至 `1.20.0` 及以上、webPage 至 `1.4.2` 及以上，然后重新探测并继续；
2. 不使用业务资源管理，按旧版非托管模式继续生成页面。

选择升级时，Agent 停止资源写入；升级完成后重新执行接口探测。选择旧版模式时，不再调用资源上传接口。

## 统一纳管模式

接口可用后，Agent 按既定内部资源工作流自动完成：

1. 获取当前业务域完整资源列表；
2. 复用已有同内容资源；
3. 下载第三方静态依赖及其有限依赖闭包；
4. 对缺失资源按批次上传且默认禁止覆盖；
5. 页面只写受管资源根下的相对路径；
6. 写入唯一的 `data-cdp-internal-resources` manifest；
7. 运行机械校验并自行处理可纠正失败。

Agent 不在生成前询问 CDP 版本。这样会接受一种已知风险：webPage 已升级而 CDP 仍低于 `1.20.0` 时，页面可能无法正确解析业务资源。

## 交付提醒

统一纳管页面交付时必须包含以下含义明确的提醒，但不阻断交付：

> 本页面已启用业务资源统一管理，webPage 资源接口已验证可用。平台无法自动识别前端版本，请确认目标环境 CDP 不低于 1.20.0；旧版 CDP 无法正确解析业务资源路径。

## 旧版非托管模式

用户明确选择旧版模式后：

- 不上传资源到 `cdn_cdp/{businessDomain}/`；
- 不写 `data-cdp-internal-resources` manifest；
- 第三方静态资源按旧规则直接引用；
- 页面由原有相对路径或外部 CDN 负责资源加载；
- 交付说明明确该页面不具备统一迁移、内网离线部署和平台依赖分析保证。

校验器必须有显式旧版模式，不能把统一纳管校验失败自动解释成旧版模式。

## 明确不做

- 不在页面运行时检测 CDN 接口或 CDP 版本。
- 不向实际应用用户展示版本选择或兼容提示。
- 不通过猜测 CDP 部署路径读取版本文件。
- 不生成同时包含托管与非托管资源引用的双轨页面。
- 不因鉴权、网络或服务异常自动降级。
- 不持久化用户的 CDP 版本确认；未来出现重复确认需求时再单独设计。

## 验收标准

1. 页面无业务资源时不调用 `listFiles`。
2. `listFiles` 成功时无用户确认，完整执行统一纳管并在交付中提醒 CDP 最低版本。
3. HTTP `404`、`405` 或响应协议不匹配时只提供升级和旧版非托管两个选择。
4. `401`、`403`、网络错误、超时、`5xx` 不进入旧版选择。
5. 旧版模式不上传、不写 manifest，统一纳管校验不会误运行。
6. 统一纳管模式仍遵守系统资源排除、禁止覆盖、相对路径和 manifest 规则。
7. 页面中不存在运行时版本探测或自动降级逻辑。
